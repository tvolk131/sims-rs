# Buy Mode Hand Tool: Move, Rotate, Sell, Depreciation & Unified Undo/Redo

- **Date:** 2026-11-21
- **Scope:** `sims-vm` (`buy`, `boot`), `sims-render` (`canvas`, `scene`), `sims-ui` (`command`, `hud`, `buy`), `sims-game` (`game`, `hud`, `main`, `tests/goth.rs`)
- **Reference:** The Sims Complete Collection 1.91 (`Sims.exe`), Track 2 oracle recording `goth-buy-move-sell-20261121`

## Decisions

### 1. Hand Tool Pickup, Click-to-Pick-Up vs Drag-to-Drop & Grab Offset
- Picking up an existing lot object (`0x485f98` → `0x486960` → `0x4215e6`) validates `CanPickUp` (`0x4352e8` / `0x422fdc`) on the object's group, captures the group lead's pre-pickup placement and all recursively contained surface children (`0x48ba19`), wraps the group in a `"Tile Cursor"` (`0x00000437`), keeps `cursor.held` and `cursor.cursor` pointing at the clicked part (so multi-tile rotation pivots around the grabbed tile and `0x486960` computes the grab offset from that tile), invokes `USER_PICKUP` (OBJf 12) + `take_off`, and immediately re-places both at the clicked tile/container so it starts valid on-lot (`before = cursor_id`).
- `CanPickUp` enforces `data[43] & 0x02 != 0`, `data[62] <= 0`, `data[8] & 0x20 == 0`, recursive `CanPickUp` on every non-empty surface child, and level-1 tile flag `0x20` clear; `buy_pick_up` also requires both the clicked part and its lead to be on-lot so detached Undo/Sell history instances can never be picked up and re-sold. Persons are never pickable.
- Screen-pixel grab offset (`[tool + 0x50]`, `[tool + 0x54]`, `0x486960`) records `click_point - cursor_screen_point` on pickup and subtracts it before terrain unprojection in `0x485a2e` so objects picked by their upper sprite (e.g. a chair backrest) track the pointer without jumping a tile. New catalog purchases use `[0, 0]`.
- Native `[tool + 0x81]` (`buy_commit_on_release`): initial pickup sets it to `false`, so releasing within `< 2 px` (`dx^2 + dy^2 < 4`, `0x4864d0`) keeps the object attached to the cursor (click-to-pick-up); dragging `>= 2 px` drops it on release, and pressing with an already-active cursor sets it to `true` so release commits. Holding Shift while dropping a moved existing object never triggers repeat purchase (`+0x75 == 0`, `0x4864d0`).
- While holding an existing lot object, the Buy Mode catalog strip switches to the native Sell Prompt (`0x487d7a` → `0x4cf90b` → `0x50a343`) formatted from `GameData/UIText.iff STR# 136` (dispose, sell with depreciated refund, or cannot-be-deleted) alongside the object's master catalog thumbnail.

### 2. Cancel Snapback, Sell, Depreciation & Unified Undo/Redo
- Cancelling a picked-up existing object (`Escape` / mode switch, `0x487191`) deletes only `"Tile Cursor"` and restores the held object and all of its surface children back to their pre-pickup placement via `0x48bfab` (`USER_PICKUP` → `take_off` → rotate → `UserTestPlace` → `put` → `USER_PLACEMENT`), with zero funds change and clearing the Redo stack (`0x4933a9`). If restoration of either the parent or any surface child is refused, `buy_cancel` / `buy_snap_back` returns an error and rolls back `world` atomically so paid furniture and children are never dropped off-lot; desktop `Escape` consumes the key instead of exiting while a Buy cursor remains held. Saving mid-pickup (`save_without_buy_cursor`) uses the same snapback on the cloned save world so an existing object or its children are never orphaned or deleted on save.
- Running Undo/Redo while the Hand Tool holds an existing lot object first snaps that object back and releases cursor ownership (`Lot::buy_snap_back`, without clearing Redo) so the Hand Tool can never double-refund, resurrect, or collide with an undone/redone record; unpaid new catalog previews stay armed (`0x4a8545` / `0x4a856a`).
- Selling (`Delete` / `Backspace` at `0x486b5b`, or clicking / dropping onto the Buy catalog strip at `0x50d04d` → `0x4cf97a` → `0x487e18`) checks `CanDelete` (`0x435440` / `0x423135`: `CanPickUp`, `data[43] & 0x08 != 0`, and all surface containment slots empty). If refused, `UI_error` plays and the cursor stays held.
- Resale / depreciation (`0x43219a`) reads the lead tile's `data[41]` (`+0x9c`) and halves it with signed integer division when any part in the group has `data[15] != 0` (`+0x68`, broken).
- Selling an existing object refunds `resale_value` via `spend(cat, -refund)`, deletes only `"Tile Cursor"`, leaves the sold object detached off-lot (`[-16, -16]`) in `world.objects` for Undo, pushes a `BuyActionKind::Sell` record onto `buy_undo`, and plays `UI_moneyback` (`0x492ad4`) for nonzero refunds or `UI_archtool_delete` (`0x492b05`) for zero-value disposal (with the native 400 ms cooldown). Selling an unpaid new catalog preview cancels and deletes both objects with `0` refund and no sale sound. Drop-to-sell hit-testing uses the 100 px Buy strip (`hud::STRIP` / `sell_prompt.rect`) so releasing in the house viewport above `y = height - 100` never triggers a sale.
- Unified Buy Mode Undo/Redo (`0x48bd21` / `0x48bdfe`) handles all three action kinds:
  - **Buy (`kind 0`):** Undo requires `placed && on_lot` (preventing double refunds if a refused Redo was transferred to Undo), then detaches and refunds `price`; Redo requires `!placed && !on_lot` and `available_funds >= price` (preventing overdrawing funds after an earlier refused Sell Redo), restores atomically (rolling back any partial parent/child placement if a child refuses), and charges `price`.
  - **Move (`kind 1`):** Undo and Redo require the target object AND every recursive surface child to be currently on-lot (so a refused `Buy` Redo can never be resurrected for free by a subsequent `Move` Redo on a parent surface), and restore the object and all recursive surface children atomically with zero funds change. A refused `Move` Redo keeps the owned object safely on-lot at `before`.
  - **Sell (`kind 3`):** Undo requires `!placed && !on_lot` and `available_funds >= price`, restores the detached object to `before`, and re-deducts `refund`; Redo requires `placed && on_lot && can_delete` (so a surface that still holds a paid child after a refused Move Redo can never be detached and deleted with its child), then detaches and refunds `refund`.
- Leaving Buy Mode back to Live Mode (`F1` / mode switch, `0x4cea5d`) executes atomically via `Lot::set_mode_releasing_buy_cursor` in exact native order: `go_live` (`0x4cea9e` → `0x416534`), `update_comeandsee` (`0x4ceac2` → `0x40726a`, walking `world.order` newest-first while detached history objects and the active Buy cursor/preview are still registered so marker IDs and positions match native), `buy_purge_detached` (`0x4ceaf5` → `0x4933dc` → `0x48c20e`, deleting detached off-lot instances owned by `Buy`/`Sell` history while protecting the active cursor's objects and any detached ancestor container holding them), Buy tool teardown (`0x4cec3a` → `0x4cef9b` → `0x487191` → `0x487105`, deleting unpaid previews or snapping back held existing objects; any snapback refusal rolls back the entire mode switch), and a final purge pass for any deferred detached ancestor containers. Saving also purges detached `Buy`/`Sell` instances.

### 3. Buy Mode Follow-ups Folded In
1. **Red-tinted blocked preview palette:** Blocked Buy previews drawn via `0x42242f` use `Canvas::draw_tinted` implementing `0x4b44eb(1)` → `0x4c76d1` → `0x4b9425(3, 0.9)` → `0x49bd78` (`gray = ((r+g+b)/3 * 0.9 + 0.5).trunc()`, `[min(255, gray + 0x30), gray, gray]` packed through RGB565 `quantize565`).
2. **Multipart `0x485f49` fit refusal:** `buy_move` only writes `cursor.position` when `0x421e72` actually runs (snapped or fallback `fits` passes), preserving the previous saved `cursor.position` on dual `fits` refusal so manual rotation (`0x421be4`) rechecks at the last valid tile.
3. **Live panel collapsed state:** `Game` preserves `live_panel_expanded` across Live → Buy/Build/Options → Live transitions (`0x4cea5d`) and re-syncs `view_centre` when `expanded` changes.
4. **Second Buy button click vs `F2`:** Clicking the Buy button while already in Buy Mode emits `Command::BuyToggleSort` (`0x53a2c3` → `0x4cf3af`), toggling `ByFunction` ↔ `ByRoom` instead of collapsing the strip, whereas `Game::set_mode` is a no-op when already in the requested mode (`0x4cea5d`) so pressing `F2` in Buy Mode preserves the open catalog and any active pickup.
5. **Buy Mode keyboard shortcuts:** Wired `F1` (Live), `F2` (Buy), `Delete`/`Backspace` (sell held), and `x`/`z` (next/prev catalog page, `0x4d0ef0`) in `sims-game`.
6. **Catalog popup card ratings:** `BuyItem` reads OBJD motive ratings `+0xa4..+0xb0` and skill flags `+0xb2` (`0x457a36`), formats them using `GameData/UIText.iff STR# 160` (`0x508168` → `0x50845d`), and dynamically sizes `PopupCard` past `127 px` so wrapped descriptions and all rating lines render visibly without clipping.
