# UI Effect (opcode 34, `0x44acff`)

## Context

`UI Effect` (opcode 34, `0x44acff`) was the last remaining unimplemented SimAntics opcode in the `0..=51` primitive table (used by the Tutorial and Help System).

## Behavior recovered from `Sims.exe`

Disassembly of `0x45226a` → `0x44acff..0x44ad89`, `0x476468..0x4764fd`, `0x47689c..0x476983`, `0x476984..0x476a17`, `0x4e9753..0x4e9783`, `0x4e92a8..0x4e93c4`, and `0x5de13f`:

- Operands: `mode = operands[0]` (unsigned byte), `scope = operands[1]` (unsigned byte), `index = i16::from_le_bytes([operands[2], operands[3]])`, `enable = operands[4] & 1`. Bytes 5–7 are unread.
- Dispatched in the general object primitive table (`0x45246a`, slot 34 → `0x45226a`), so both persons and non-person objects execute `0x44acff`.
- **Mode 0 (`0x44ad3f`)**: reads `self.read(scope, index)` (`0x453141`), highlights the matching `cTSWinBtn` (`0x476468` → `0x5de13f`, presentation only), and **falls through into mode 1** (`0x44ad61` — no `break` in the original `switch`), reading `self.read(scope, index)` a second time and calling `0x47689c`.
- **Mode 1 (`0x44ad61`)**: reads `self.read(scope, index)` (`0x453141`) and calls `0x47689c`:
  - Looks up the 1-based neighbor record (`0x4256f4`); returns immediately if none.
  - Looks up its GUID (`0x5ed65e`, record `+4`) in the interface person portrait table (`0x4e9753`, pure linear scan).
  - Calls `0x4e92a8(index, &bitmap)` **unconditionally** (even when `enable == 0`), which builds the person's portrait via `0x4e8c5d` / `0x4e9652` if listed and not yet cached (shared with `Dialog`'s portrait via `Machine::ensure_portrait`), then highlights the matching `cTSWinBtn` (`0x47692b` → `0x5de13f`, presentation only).
- **Mode 2 (`0x44ad1f`)**: reads `self.read(scope, index)` (`0x453141`) and calls `0x476984`, which looks up the neighbor (`0x4256f4`) and its read-only index (`0x4e9753`) and highlights `cWinRelationship` (`0x4769ca` → `0x5de13f`, presentation only). Does **not** call `0x4e92a8`.
- **Modes `>= 3` (`0x44ad1d`)**: skip `0x453141` and do nothing.
- All modes return `true` (`0x44ad83`).

## Verification

- Covered by synthetic tests in `crates/sims-vm/tests/interpreter/ui_effect.rs` (mode 0 fallthrough into mode 1, mode 1 portrait building and caching on both `enable = 0/1` and person/non-person callers, variable scopes, missing/non-person neighbors, on-lot person vs household/runtime-made guards, mode 2 read-only behavior, mode `>= 3` skipping variable reads, and `0x453141` native error checks).
- **Unverified against a Windows recording**: none of the current Goth or expansion recordings execute opcode 34 (Tutorial / Help System only).
