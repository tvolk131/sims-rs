# UI Effect (opcode 34, `0x44acff`)

## Context

`UI Effect` (opcode 34, `0x44acff`) was the last remaining unimplemented SimAntics opcode in the `0..=51` primitive table (used by the Tutorial and Help System).

## Behavior recovered from `Sims.exe`

Disassembly of `0x45226a` → `0x44acff..0x44ad89`, `0x45412b..0x4541dd`, `0x476468..0x4764fd`, `0x47689c..0x476983`, `0x476984..0x476a17`, `0x4067b3`, `0x4174dc`, `0x41bab1..0x41badc`, `0x4e88fa..0x4e89d5`, `0x4e8a44..0x4e8bae`, `0x4e8c5d..0x4e8ff6`, `0x4e9000`, `0x4e9260..0x4e93c4`, `0x4e9608..0x4e9783`, `0x4dece6..0x4ded49`, `0x4f6727`, and `0x5de13f`:

- Operands: `mode = operands[0]` (unsigned byte), `scope = operands[1]` (unsigned byte), `index = i16::from_le_bytes([operands[2], operands[3]])`, `enable = operands[4] & 1`. Bytes 5–7 are unread.
- Dispatched in the general object primitive table (`0x45246a`, slot 34 → `0x45226a`); `cXPerson` forwards opcode 34 to the general dispatcher (`0x45cbb3` → `0x45cc46`).
- **Global 34 (`0x45412b` → `0x4541d5`)**: `0x44acff` never initializes `[object + 0x128]` (zeroed at `0x431a77`), and `0x45412b` unconditionally writes `&globals[34]` through `[object + 0x128]` even with `write == 0`. Modes 0–2 fail loudly (`Trap::Unsupported`) on scope 6, index 34.
- **Mode 0 (`0x44ad3f`)**: reads `self.read(scope, index)` (`0x453141`), highlights the matching `cTSWinBtn` (`0x476468` → `0x5de13f`, presentation only), and **falls through into mode 1** (`0x44ad61` — no `break` in the original `switch`), reading `self.read(scope, index)` a second time and calling `0x47689c`.
- **Mode 1 (`0x44ad61`)**: reads `self.read(scope, index)` (`0x453141`) and calls `0x47689c`:
  - Looks up the 1-based neighbor record (`0x4256f4`); returns immediately if none.
  - Looks up its raw GUID (`0x5ed65e`, record `+4`) in `0x6f2698` (`0x4e9753`). Startup (`0x4e8b3d`) adds every catalog definition with `object_type == 2` (even if a later non-person definition shares the GUID), and `Make New Character` (`0x4262d8` → `0x43c5fc` `0xe0` → `0x4f6727` → `0x4e8a44` → `0x4e8add`) appends runtime-made person GUIDs.
  - Calls `0x4e92a8(index, &bitmap)` **unconditionally** (even when `enable == 0`):
    1. If the slot's rebuild/dirty flag (`[entry + 0x18]`, cleared at `0x4e88fa` and set by `0x4e895e` / `0x4eb0eb`, tracked in `World::dirty_portraits`) is set, calls `0x4e8c5d(index, 1, 0)` first (`0x4e92f2`, save flag `0`: does not write `BMP_` 2002).
    2. If the slot now holds a cached image (`World::portraits`, `0x4e931c`), stops.
    3. Otherwise tries neutral-language `BMP_` 2002 (`0x7d2`, high byte of flags `0`, `0x4e9338` → `0x4e9260` → `0x4dece6` → `0x41cb2f` → `0x41bab1` / `0x41bad8`, recorded in `Library::has_portrait_2002` or persisted earlier in `World::generated_portrait_2002`). If present and decodable, caches it (`0x4e899e`, clearing dirty) without creating a temporary Sim or touching RNG.
    4. Otherwise calls `0x4e8c5d(index, 1, 1)` (`0x4e938c`, save flag `1`: on success for a writable file, `0x4e8d2e` → `0x4e9000` → `0x4e8feb` writes `BMP_` 2002 into the winning definition's IFF file, tracked per file in `World::generated_portrait_2002` and reloaded by both `UI Effect` and `Dialog` when the winning definition is a person (`0x43639e` → `0x4575d2`) on clean uncached slots — including runtime-made characters — and after a failed dirty rebuild at `0x4e9706`).
  - Inside `0x4e8c5d`, an on-lot person (`0x4e9608`) is reused without creating a Sim. Otherwise `0x4e8cc6` checks resource writability (`0x4067b3` → `0x4174dc`, tracked via `Library::read_only`; runtime-made `User%05d.iff` files are writable) and skips `0x4e9652` when read-only (e.g. `.far` archive members such as `TemplatePerson.iff`). When writable, `0x4e9652` has no household-membership guard, handles factory `0` (`0x4e969d`, including the early `0x440d63` `"dog"`/`"kat"` expansion check for both runtime-made and catalog pets before `.bcf` skeleton load), non-person `dynamic_cast` failure (`0x4e96b7` → `0x4e96c3`), and no-tile removal (`0x4e9706`). `0x4e8d02` checks the portrait renderer result (`0x4e725f` → `0x4e7817` → `0x4e810d` → `0x4e81a4` → `0x431726` → `0x4e7824`, requiring an exact case-sensitive `"HEAD"` binding with no whitespace trimming per `0x5874ca`/`0x5a27f2`, tracked in `People::head_suits`, `People::portrait_head`, and `World::made_portrait_head` for `Make New Character` wardrobe selections — including pet creation's immediate `0x4e8c5d(index, 0x1f, 1)` render at `0x44b126` which preserves Init/CRT RNG without faulting opcode 19 on mixed custom pet wardrobes and tracks `BMP_` 2002 while leaving presentation-only `BMP_` 2003–2007 unmodeled, `0x40a5e2` clearing head row 2 to `"NONE"` on invalid pet-picker indices, `0x44b2d7`/`0x44b2ef` (`0x472f92`) 63-byte-buffered wardrobe lookups on negative-age copies, and failing loudly when `UI Effect` or `Dialog` queries a mixed-wardrobe character whose `"HEAD"` binding depends on unmodeled wardrobe order), then caches (`0x4e8d14`) and stages `BMP_` 2002 (`0x4e8d2e`) **before** removing the temporary person at `0x4e8fdb` (so a removal/Reset callback can still invalidate the portrait via `0x44e712` → `0x4e895e`, while `0x4e8feb` flushes the staged `BMP_` 2002 afterwards).
  - Highlights the matching `cTSWinBtn` (`0x47692b` → `0x5de13f`, presentation only).
- **Mode 2 (`0x44ad1f`)**: reads `self.read(scope, index)` (`0x453141`) and calls `0x476984`, which looks up the neighbor (`0x4256f4`) and its read-only index (`0x4e9753`) and highlights `cWinRelationship` (`0x4769ca` → `0x5de13f`, presentation only). Does **not** call `0x4e92a8`.
- **Modes `>= 3` (`0x44ad1d`)**: skip `0x453141` and do nothing.
- All modes that complete return `true` (`0x44ad83`).
- `World::dirty_portraits`, `World::generated_portrait_2002`, and `World::made_portrait_head` stay `#[serde(skip)]` on `World` (preserving snapshot format 31 wire bytes), are compared in `both_ways::same_lot`, and are persisted in `sims_vm::boot::save::Saved` (save layout 6).
