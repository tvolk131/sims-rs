# HIT 20 ms (50 Hz) Periodic Sound Timer

## Context

Previously, `sims-audio` stepped HIT track scripts and fades once every `BLOCK` (64 frames at 22,050 Hz, ~2.90 ms) while stepping the kind-25 volume-nudge countdown (`0x573019`) on the 20 ms (`TIMER_FRAMES = 441` frames, 50 Hz) timer. That left all HIT fades running ~6.9× faster than Complete Collection 1.91 (for example, `FadeAndKillTrackSlow`'s `fade_speed = 3` finished in ~0.99 s instead of ~6.84 s), treated `wait` operands as milliseconds instead of 20 ms HIT ticks, polled `wait_samp`/`waiteq..waitle`/`seqgroup_kill` at 64-frame boundaries instead of 2 HIT ticks (40 ms), yielded artificially on `loop` and self-restarting `play_trk`, and used a 10,000-step / 100,000-budget loop limit instead of 1.91's 102-instruction per-track cap.

## Disassembly Findings (Complete Collection 1.91)

- **Periodic timer (`0x572fc3` → `0x572fd6`):**
  The sound manager installs a 20 ms (`push 0x14`, exactly `TIMER_FRAMES = 441` frames at 22,050 Hz) periodic timer (`0x607461` adds the 20 ms delay to current time at sound-manager init). Callback `0x572fd6` checks the initialized flag `[0x6f640c]`, runs the kind-25 volume-nudge countdown (`0x573019..0x573038`), increments `[manager + 0x14]` (`0x57303a..0x573043`), and calls `0x57cf37` on the HIT engine (`[0x6f6ac8]`). Both nudge and HIT execute atomically in that single callback, with nudge before HIT.
- **HIT engine tick (`0x57cf37..0x57d016`) and clock (`[hit + 0x58]`):**
  The HIT constructor (`0x57c9b8..0x57c9c5`) initializes `[hit + 0x58] = 1`, `[hit + 0x54] = 1`, `[hit + 0x60] = 1`, and error callback `[hit + 0xc8] = 0x57bd45` (`0x57c76a`, which logs the message and calls `Track::Kill`, `vtable[+0x38]` at `0x57bd91`). On each 20 ms tick, `0x57cf37` increments `[hit + 0x58]` by `1` (`0x57cf74`), snapshots the running track list (`[hit + 0x2c]`), and calls `vtable[+0x1c]` (`0x57d7cd`) on every running, unheld track.
- **Unpause clock increment (`0x57cd2c`):**
  Before walking the registry to call `let_go` (`vtable[+0x5c]`, `0x57dc63`, setting each track's wake tick `[esi + 0x198] = [hit + 0x58]`), `0x57cd3e..0x57cd46` increments `[hit + 0x58]` by `1`.
- **Track tick (`0x57d7cd..0x57d95f`):**
  1. Returns immediately if `!running` (`[esi + 0x1c4] == 0`) or `held` (`[esi + 0x1c8] != 0`).
  2. Steps any active fade once per 20 ms tick (`0x57d7ff..0x57d868`), and kills the track (`0x57dd3e`) if `kill_after_fade` (`[esi + 0x1cf]`) is set and `fade_on == 0` (`0x57d86e..0x57d88d`, returning early and skipping `0x57d929`).
  3. Snapshots `[hit + 0x58]` (`0x57d898`); if its sign bit is set (`0x57d89b..0x57d8a8`), invokes `0x57bd45` (`Track::Kill`).
  4. Runs instructions while `wake != 0 && saved_clock >= wake` using unsigned comparison (`jb` at `0x57d8c0`), invoking `0x57bd45` (`Track::Kill`) if `wake` has its sign bit set (`0x57d8c2..0x57d8d1`) or after executing the **102nd** instruction in one tick (`0x57d909..0x57d91f`: post-instruction `cmp eax, 0x64; jle`). There is no cross-thread shared instruction budget deferring other tracks.
  5. Checks timed `note` auto-stop (`0x57d929..0x57d951`): if `[esi + 0x194] != 0 && saved_clock >= [esi + 0x194]`, stops the active voice (`vtable[+0x98]`) and clears `[esi + 0x194] = 0`. `[esi + 0x194]` is initialized to `0` once in the track constructor (`0x57d6b6`) and is **not** cleared by `Track::Start` (`0x57da3a..0x57dbc5`) or `Track::Kill` (`0x57dd3e`).
- **Opcode timing and validation:**
  - `note` (op 1, `0x57e145..0x57e18d`): validates both register operands `<= 127` (`0x57f561` → `0x57bd45` `Track::Kill` on `> 127`), arms persistent `[esi + 0x194] = [hit + 0x58] + duration` (20 ms ticks), and calls `note_on` (`0x57f595`).
  - `wait` (op 9, `0x57e42d..0x57e463`): validates register in `1..=127` (`0x57f561` + zero check → `0x57bd45` `Track::Kill` on `0` or `> 127`), reads the register in **20 ms HIT ticks** (verified against `SimsSound.hit` `MainMusicLoop` `loadl r5, 250; wait [5]` = 5.0 s and `loadl r5, 50; wait [5]` = 1.0 s), and writes `[esi + 0x198] = [hit + 0x58] + ticks`. A `0`-tick wait leaves `wake == hit_clock` and continues executing in the same tick.
  - `wait_samp` (op 11, `0x57e468..0x57e485`), `waiteq..waitle` (ops 77..82, `0x57e48a..0x57e6cd`, validating both operands in `1..=127` via `0x57f561` + zero check → `0x57bd45` `Track::Kill`), and `seqgroup_kill` (op 69, `0x57eef3..0x57efe6`): when blocked, keep `pc` on the instruction and set `[esi + 0x198] = [hit + 0x58] + 2` (`inc eax; inc eax` = **2 ticks = 40 ms = 882 frames**).
  - `loop` (op 32, `0x57ee33..0x57ee3b`): jumps to `loop_point` in the same tick without touching `[esi + 0x198]`.
  - Self-restarting `play_trk` (op 50, `0x57f1f2` → `0x57dc0d` → `0x57dc8e` → `0x57f267`): calls `let_go` setting `wake = hit_clock` and returns directly to the current tick's instruction loop (continuing in the same tick, bounded by the 102-instruction cap).
- **Ambience cadence (`cFreshPlayer::Update`, `0x577ab9`):**
  1.91 calls `cFreshPlayer::Update` per frame, reading elapsed milliseconds at `0x577b86` and checking lateness (`now - due > 7`) at `0x577bfa`. Keeping `step_ambience` on `BLOCK` (64 frames, ~2.9 ms) preserves `sims-audio`'s existing sub-7 ms scheduling approximation without claiming frame-exact beat placement against 1.91's variable frame loop.

## Decisions

1. **Drive HIT track/fade execution from a unified 20 ms (`TIMER_FRAMES = 441`) timer callback in `crates/sims-audio/src/player.rs`:**
   - Replace the split `ran_at`/`nudged_at` guards with a single `ticked_at: Option<u64>` so nudge (`0x573019`) and HIT (`0x57cf37`) execute atomically in native order on every `TIMER_FRAMES` boundary and nudge can never run after HIT on the same frame.
   - Keep `Player::new` aligned to initial timer phase `frame == 0` (preserving `sims-audio`'s existing API contract where a freshly created `Player` models an already-running sound manager aligned to a timer tick rather than inserting 20 ms of startup silence before the first callback as `0x572fc3` → `0x607461` does at app boot) and keep `StopAll` (`kind 20`) leaving the timer active so subsequent `play()`/`camera_moved()` calls continue working without re-initialization (noting 1.91 cancels the timer via `0x572fc9` at `0x573c16`).
   - Maintain `Player::hit_clock: u32` initialized to `1`, incremented once per `TIMER_FRAMES` tick in `step_timer` and once in `unpause_tracks` (`0x57cd46`).
   - Switch `Thread::wake` to HIT ticks (`u32`), store persistent timed-`note` deadlines in `Player::note_off: BTreeMap<u32, u32>` (preserved across kill/restart and cleared only on `0x57d929..0x57d951` expiry or `destroy` at `0x57ce04`), check signed-clock (`0x57d89b`) and signed-wake (`0x57d8c2`) overflow diagnostics, enforce 1.91's per-track `STEPS = 102` post-instruction cap (`0x57d909..0x57d91f`) without cross-thread budget deferral, validate `note`/`wait`/`waiteq..waitle` register operands fatally (`0x57bd45` → `Track::Kill`), set `Flow::Block` to sleep `POLL_TICKS = 2` ticks (40 ms), and run both `loop` and self-restarting `play_trk` in the same tick.
   - Advance `render_stereo` and `render_until_idle` to `until_timer.min(until_block).min(remaining)` so HIT ticks stay on exact 441-frame boundaries while ambience updates remain on `BLOCK = 64` boundaries.
2. **Update tests and pinned install digests:**
   - Update `crates/sims-audio/tests/player.rs` to `TIMER_FRAMES` (441-frame) ticks, 20 ms `wait` units (`waits_a_second` = 50 ticks, local register `15` for scratch loops), and `POLL_TICKS = 2` boundaries, and add regression tests for 20 ms fade stepping, `wait 0` and fatal bad-register handling in `wait`/`waiteq`/`note`, `STEPS = 102` boundary and non-deferral, persistent timed-`note` deadlines across interrupt restart and kill, same-tick finite and runaway self-restarting `play_trk`, `unpause` clock increment, and unified `ticked_at` callback ordering.
   - Update `crates/sims-audio/tests/install_player.rs` (`the_phone_rings` 58,212 frames = `66 * 882` at the 40 ms `wait_samp` poll; `a_sim_takes_a_soft_footstep` same chosen patches with 40 ms tail; `the_backyard_ambience_plays` same ambience cursor `(13, 6)` and active count `3` with 6.84 s neighbourhood music fade-out; `every_event_definition_runs_without_a_bad_instruction` 183 still-running events after 20 HIT ticks = 400 ms with 0 unported instructions and one `STEPS = 102` runaway kill on `playtag_laugh_vox` track 3928, whose child-only `call 0x103; loop` genuinely spins without waiting under `NoSources` gender `0`) and `crates/sims-game/tests/sound.rs` (`pausing_the_lot_pauses_live_ambience_and_night_loop` draining `bkground_live`'s 6.84 s slow fade of `PAUSE_SPARES` `MainMusicLoop` while paused).
